# TOMC-Keep Advancing

> 📘 **数据包与触发器参考** — [datapack.zh-CN.md](datapack.zh-CN.md)

**TOMC-Keep Advancing** 是 TOMC 系列的进度层，一个**几乎纯数据包驱动**的 Fabric 进度模组。它加入一个 **TOMC 选项卡**和 **22 条挂进原版各标签页里的新进度**，另外提供**五个触发器**，让一份普通 JSON 能表达原版进度格式表达不了的东西：时间窗、已加载的模组、一组进度、开着哪个界面、附近有没有某座结构。内容是 JSON，Java 侧只为"JSON 说不出口的那部分"存在——而它的每一块都可以关掉，关完剩下的是一个别的模组可以直接依赖的触发器库。

## 特性

### 🏆 一个认得整个系列的选项卡

只要你在跑这个系列里的**任何**其它模组，TOMC 选项卡就会出现——而它靠的是 **Java 包名**，不是 modid：

- 它的根节点判据是 `keepadvancing:mod_loaded` 配正则 `io\.github\.thatone0502`。一个模组只要是**这个作者**做的就算数；**将来新增一个 TOMC 模组，不需要改动这里的任何一个文件**就会被认出来。
- 判定发生在**玩家加入时**。模组集合开服后就固定了，所以这不是每 tick 轮询，结果会被缓存下来。
- `exclude_self` 默认为开，所以它不会把根节点发给自己。它是一个关于**其余** TOMC 模组的模组。
- 选项卡自带一张 **16×16 平铺背景**，而不是去引用某张原版方块贴图——原版整理贴图时移不动它。
- 原版进度格式里**没有独立的「选项卡名」字段**：左下角那个标签显示的就是**根节点的标题**。所以它显示的是「欢迎来到“TOMC”」而不是一个光秃秃的 "TOMC"。这也是为什么根节点是全模组唯一一个标题在同时干两件事的条目。

### 🥚 22 条织进原版标签页里的进度

它们**不是**被收在 TOMC 选项卡下面，而是**原版既有进度的子节点**——所以你会在本来就会看的地方看见它们：

- 望远镜那一组从 `minecraft:adventure/root` 和原版自己的 `spyglass_at_*` 节点上长出来：**那是什么？** → **那是拴绳吗？** → **太炸裂了**，以及 **那是妹子吗？**、**那是要见鬼吗？**、**那是航站楼吗？** → **你不要过来啊~**。
- 神庙那一组是一条五连环，起点挂在原版节点上，终点又**绕回去**改了原版节点：**劫掠**（村庄）→ **古埃及的智慧**（沙漠神殿）→ **古玛雅的智慧**（丛林神庙）→ **林地探险家**（林地府邸）→ **海洋探险家**（海底神殿）→ 而它又重定父了原版的**探索的时光**与**边境之地**。
- 其中四条是**达成前隐藏**的，行为与原版隐藏进度完全一致：**我要当太空人**、**你个怪物！**、**植物大战僵尸**、**你已飞升**。
- 六条带**经验奖励**：终极奉献…再一次…、林地探险家、海洋探险家各 +500；我要当太空人、你已飞升、边境之地各 +12000。

### ✂️ 六处被改动的原版进度

有六个原版文件被**刻意覆盖**，其中只有两处是纯外观，另外四处是为了让新链有地方可挂：

| 原版进度 | 改动 |
|---|---|
| 那是鸟吗？（`spyglass_at_parrot`） | 前置 → **太炸裂了** |
| 那是气球吗？（`spyglass_at_ghast`） | 前置 → **那是妹子吗？** |
| 那是飞机吗？（`spyglass_at_dragon`） | 前置 → **那是什么？** |
| 探索的时光（`adventuring_time`） | 前置 → **海洋探险家** |
| 魔女审判（`very_very_frightening`） | 图标 → 引雷 I 的三叉戟 |
| 终极奉献（`obtain_netherite_hoe`） | 图标 → Damage 2031 的下界合金锄 |

因为原版自己的节点现在坐在新节点**下面**，完成一条 TOMC 条目也就成了"通关原版标签页"的一部分；又因为这些是**同名注册表 id 的覆盖**，**另一个改动同样这六个文件的数据包或模组会和它互相覆盖**（谁后加载谁生效）。它们被单独放进一个内置数据包，正是为了让这件事能一击开关；见[配置](#配置)。

### 🏅 TOMC奖杯

一个方块，占两格，两种右键，没有界面：

- **右键**——空手或手持任意物品都行——获得**幸运 II、10 分钟**，配紫水晶放置音效。没有冷却，想刷就刷。
- **潜行 + 空手右键**把整座奖杯（两半）**直接收进背包**，不生成掉落物实体。选中槽被占就退到整个背包，只有背包也满了才在方块处正常掉落。
- 潜行 + **手持物品**右键交还给原版：放置手里的物品，不碰奖杯。
- 它从头到尾都是一个**金属**方块——放置、破坏、脚步音效，掉落需要正确等级的镐子；整个模型由下半格画出来，所以上半格不可能和它不同步。

### 💌 全进度达成的那封信

有一个隐藏节点，职责是给**整个 TOMC 系列**收尾，而不只是本模组：

- 它的判据是 `keepadvancing:advancements_made` 配 `after: keepadvancing:tomc/root`——也就是**任何 TOMC 系列模组挂在同一个 TOMC 根节点下的进度都算数**，不需要维护一张 id 清单。以后新出的同系列模组，只要把内容 parent 到根节点，就自动进入统计。
- 单独运行本模组时这个集合解析出 **0 条**，节点永远不会触发。这是**设计**，不是没做完：根节点本身由模组加载触发，所以选项卡照常出现、什么都不坏，只是暂时还没有可供"全收集"的对象。

- 奖励会以玩家本人的身份跑一个**函数**，播放原版的挑战达成音效，并在聊天栏贴出一封八行留言，落款 *—— ThatOne*。
- 随之发放的**奖杯把同一封留言作为自己的描述（lore）**，金色、非斜体，而不是原版默认的灰色斜体。
- 留言是**可翻译组件**，所以中文客户端和英文客户端读到的是各自语言的同一件物品。但**第一行里的名字不是**——它在奖杯发放的那一刻被解析成字面文本烘了进去，这正是它能被丢给别人、而对方读到的是**你**的名字的原因。
- 通过其它任何途径拿到的奖杯——创造模式拿的、潜行空手捡起的、放置后再挖回来的——**都没有 lore**，因为没有"发放瞬间"可以烘名字。

### 🧰 给数据包作者的五个触发器

这一部分是留给"作者不是本人"的场合用的。五个全部由 JSON 声明，谁都不用写 Java：

| 触发器 | 它回答的问题 |
|---|---|
| `keepadvancing:timer_test` | 某个值在时间窗里怎么变的？（7 种算法、6 个内置仪表、任意原版统计） |
| `keepadvancing:mod_loaded` | 环境里有没有包名匹配这个正则的模组？ |
| `keepadvancing:advancements_made` | **一组**进度里做完了多少（或占多大比例）？ |
| `keepadvancing:gui_open` | 玩家此刻看着的是哪个界面？ |
| `keepadvancing:structure_present` | 附近有没有 100% 一致的结构？ |

它们是自带内容得以成立的原因——"1 秒内潜行 5 次"和"30 秒内用掉 10 个图腾"在原版格式里根本写不出来——但它们对别人自己的进度树同样好使。完整字段表与现成配方：[datapack.zh-CN.md](datapack.zh-CN.md)。

### 🎨 三项显示扩展

三个加在原版进度格式上的可选扩展，全部向后兼容：

- **`icon` 可以是字符串。** 写 `"icon": "mymod:icon/star"`，这条进度画的就变成一张纹理而不是一个物品。物品写法一如既往照旧可用。
- **`background` 可以是对象。** `mode`（`tile` / `fill` / `cover` / `contain`）与 `attachment`（`fixed` / `local`）把选项卡背景从一张钉死的 16×16 平铺图，变成能缩放、裁切、或跟着内容滚动的东西。写普通字符串仍然是"tile + fixed"，也就是原版行为。
- **`multi_parents`。** `parent` 仍是主父、仍然决定解锁链，`multi_parents` 只**多加画出来的连线**——于是一个节点可以从好几条分支视觉上汇合，却不因此多出解锁路径。位置在**服务端**算好随进度下发，客户端一分钱不花。

### 📚 库模式

一个配置键 `load_builtin_content`，决定这个模组是**内容**还是**基建**：

- `true`（默认）：TOMC 选项卡、22 条进度、奖杯方块、六处原版改动，全部加载。
- `false`：**我们的内容一件都不加载**——没有选项卡、没有方块、不覆盖任何原版文件——剩下的就是五个触发器加公开 GUI API，作为一个纯前置库。

五个触发器和那个 API **永远**会注册，开关从来不碰它们。而且开关关掉时，**原版进度一条不少**（实测 1584 条），包括那四条本来会被内置数据包重定父的。

## 设计思路

四条原则决定整个模组：

1. **内容是数据，Java 只负责 JSON 说不出口的部分。** 这里的每一条进度都是一份数据包自己也能写的 JSON 文件。Java 侧只提供五个触发器，此外对一个想加新判据的作者毫无要求。
2. **只做追加；一旦要覆盖，就大声说出来。** 22 条进度是原版链上普普通通的子节点。我们确实覆盖的那六个文件列在一张表里、放在一个能一击开关的数据包里，而那个配置开关存在的理由就是它们。
3. **它是前置，不是一个"你得想要它"的内容模组。** 五个触发器的意义在于：别的模组可以依赖本模组、把自己的内容关掉，然后拿到一套进度系统，而不是拿到别人的成就列表。
4. **降级，不崩。** 未知的 `mode` 或 `attachment` 退回默认值并打一条警告；写坏的 `multi_parents` 边被跳过并打一条警告；BetterAdvancements 那套支持声明为 `required: false`、所有注入点 `require = 0`——所以那个模组将来重写，代价是一条日志，而不是一次启动失败。

## 环境要求

- **Fabric**（本仓库目前针对 **Minecraft 1.21.11**、Fabric Loader **0.19.3+**、Java **21+** 构建与测试）
- [Fabric API](https://modrinth.com/mod/fabric-api) —— 必需
- [BetterAdvancements](https://modrinth.com/mod/betteradvancements) —— 可选，且**已兼容**。BetterAdvancements 会用自己的界面顶掉原版进度界面，所以只改原版控件的模组在它下面等于没改；本模组为它另带了一套钩子，三项显示扩展在那边同样生效。

**两端都要装本模组，且版本必须一致。** 这不是软要求：

- **客户端半边**负责上报"玩家此刻开着哪个界面"，`keepadvancing:gui_open` 需要它。
- **两端都扩展了原版自己的进度网络格式**——进度上的 `multi_parents`，以及显示信息上的图标/背景字段。两端都不做版本协商；对方只会读到它不认识的字节。

所以纯原版客户端连不上装本模组的服务端，反过来也一样。这是为了支持 `multi_parents` 与背景模式、又不另开一条自己的通道而主动付的代价。

> 源码结构是"每个加载器 × 版本一个目录"（目前只有 `fabric-1.21.11/`），各自自带 wrapper 与构建。Fabric 上的 1.21.11 是**目前存在**的那个目标，而不是"将来也只会有这一个"的声明。

## 配置

`config/keepadvancing.json`，首次启动时生成：

```json
{
  "_readme": "Set load_builtin_content to false to use TOMC-Keep Advancing as a trigger library only.",
  "load_builtin_content": true
}
```

| 值 | 行为 |
|---|---|
| `true`（默认） | 全部：TOMC 选项卡、24 份进度文件、TOMC奖杯，以及被调整过的那六处原版进度 |
| `false` | 我们的内容一件不留。只剩五个触发器与公开 API |

文件不存在、字段缺失、类型不对，一律**退回默认值**而不是失败；文件写坏会被报告并替换成一份干净的。改动在数据包重载（`/reload`）或重启后生效，因为这些数据文件是被一条在数据包加载期间求值的资源条件过滤的。

那六个被覆盖的原版文件**没有**走这条路——它们住在一个内置数据包（`resourcepacks/content-data/`）里，只在开关打开时才注册。原因是一条如果你也发数据就该知道的规则：**资源条件跳过某个文件时，低优先级数据包里的同名副本并不会接管——那个 id 会整个消失。** 用那种直接做法，开关一关会悄悄删掉六条**原版**进度（1584 → 1578）。

## 从源码构建

当前目标的构建在 `fabric-1.21.11/`，它自带 Gradle wrapper；仓库根目录的 `root.gradle.properties` 持有共享版本钉选。所有构建都走 wrapper：

```sh
cd fabric-1.21.11

# Windows
gradlew.bat build

# Linux / macOS
./gradlew build
```

首次构建会下载 Minecraft、一个 JDK 21 工具链和 Fabric 依赖，比之后的构建慢得多。有两个细节是刻意的，不要"顺手清理掉"：

- `gradle.properties` 里钉住了 `org.gradle.java.home` 指向一个 **JDK 21** 安装，因为开发机 `PATH` 上的 `java` 是 Java 8，Gradle 9 在它下面根本起不来。
- `org.gradle.configuration-cache` 设为 `false`，这是 fabric-loom 一个已知 issue 的官方绕法。

产物名里带一个构建次数：

```
tomc-keepadvancing-0.1.0.<构建次数>-fabric+mc1.21.11.jar   →  build/libs/
```

前三段版本号来自 `mod_version`；第四段每次真正产出 jar 时 +1（编译失败不消耗编号）。想复现某个既有产物名而不消耗编号，用 `-PbuildNumber=7`；想额外把 `src/testdata/katest/` 下的验收测试数据包一起打进去，用 `-PwithTestData`——它**不属于**发布产物。

单个目标的构建细节——目录地图、数据包布局、显示扩展，以及每一个已经踩过的坑的留档——都在 [fabric-1.21.11/README.md](../fabric-1.21.11/README.md)。
